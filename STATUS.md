# damon-ade (RyanOS)

Personal fork of per-simmons/damon-ade — an Electron ADE ("agentic development environment") rebranded to **RyanOS**: one desktop cockpit to run all agents, organized into Teams → Agents → tabbed terminal sessions with per-agent memory and a multi-model runtime picker.

## Now
- **THE PIPELINE HAS A PRODUCER NOW — `stock-queue`, Mondays 07:00 (2026-08-09, `22f66ed`, LaunchAgent loaded).** Every job in this repo was reactive: doors turn what Ryan hands over into drafts, the drain ships what he approves, and **nothing ever STARTED a post**. That is the whole reason "healthy and idle" could be true for three weeks. Now, if the approvable shelf is below 10, it shops the Google Drive library (216 real product photos, dormant since 2025), asks Sonnet to describe each picture **from the picture**, and feeds the answer into the same `createDraft` path every door uses. It cannot approve and cannot publish. **The premise was checked before the code was: the live queue read 15 scheduled / 15 skipped / 1 published / ONE pending** — the Name On It campaign is booked through Aug 22 and behind it the shelf was empty. Three decisions carry the file: **scheduled is not inventory** (counting booked posts as stock would stop production exactly as the queue runs dry); **the ledger records on consideration, not on success** (else one unusable image is re-picked first every week forever while the other 215 are never reached); **the hint may not guess** — it is the one input the caption writer trusts completely, so a hallucinated material becomes a confident lie the linter cannot catch, because the rule bans *listed* claims, not *false* ones. `MAX_PER_RUN` = 5 makes a miscount cost five calls instead of a runaway.
- **Intake takes VIDEO, and reads Google Drive (2026-08-09, `a1dc7da`).** All three doors filtered on their own image-only extension table, so the pipeline could PRODUCE a Reel (`make_reel.sh`) and had **no way to take one back in**. Blotato's upload was never the constraint — it presigns on the filename and PUTs whatever bytes it is given — the filter was, three copies wide. One `MEDIA_TYPES` table now feeds the folder door, the Telegram door (which also learned `msg.video`) and the web form's `accept`. Drive needed **no API and no OAuth**: Drive for Desktop mounts `My Drive/Social Media/` as an ordinary path, so the door `readdir`s it. Both roots are scanned rather than cut over, so a drop where it already worked doesn't silently stop making cards. **A subfolder one level down is intent**: `Reel`/`Post`/`Story` set the platforms, any other name becomes context on the hint — a typo degrades to context (visible on the card) rather than to a wrong platform (not visible). Live end-to-end: a real photo through `_Drop/Post/` → pending draft routed `instagram + facebook`, moved to `processed/` exactly once.
- **The voice linter is IN THE REPO and runs on every draft (2026-08-09, `a1dc7da`) — superseding the `## Now` line below.** `lint_voice.py` lived in a session scratchpad under `/private/tmp`, one cleanup from gone, and nothing linted the copy `intake.ts` itself writes. **The rules lived only in the prompt, which is a request, not a check.** `lintVoice()` imports the SAME `charLimits()` the ship gate enforces, so a caption cannot pass intake and then be blocked for a cap intake measured differently. On a failure it spends exactly ONE more `claude -p` call **with the failures named** — a blind re-roll fixes nothing, and loop-until-clean cannot terminate against a model that keeps missing the same rule. What survives is written under `## Voice check` and into `grade:`, so the card warns instead of lying. **That heading is load-bearing** — it terminates the copy section, so the warning can never become published copy. Test-pinned, because the near-miss it resembles (a `video-script` note one field-edit from being published as a caption) already happened once.
